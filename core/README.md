# core

The categorizer as one pure Go function, `trace.Categorize(bank, replies)`, used natively by the
API (`backend/`) and compiled with TinyGo to WebAssembly for the browser (`web/`).

```bash
go test ./...                                                     # golden cases from pipeline/scoring.py
tinygo build -o build/trace.wasm -target=wasm-unknown -no-debug -opt=z ./cmd/wasm   # ~26 KB
node cmd/wasm/golden_test.mjs build/trace.wasm                    # same golden cases against the WebAssembly build
```

- `trace/` — bank reader (`bank.go`), parser, features and scoring. No I/O, globals, goroutines,
  reflection or `encoding/json` in the scoring path, so TinyGo can compile it.
- `internal/mtfb/` — generated by `flatc --go -o core/internal schema/bank.fbs`.
- `cmd/wasm/` — the browser entry points (`buffer`, `load_bank`, `count`, `minimum`, `categorize`;
  call `_initialize` first). The calling convention is documented at the top of `main.go`.
- `trace/testdata/golden.json` — written by `python -m pipeline.golden`; regenerate it with every bank.
