# pipeline

Offline Python: collect reference answers, build the fingerprint bank, export it for the Go core.
Nothing here runs in production; the site and the API only read the files it writes to `data/bank/`.

```bash
python -m pip install -r pipeline/requirements.txt
python -m pipeline.build                      # data/bank/bank.json, bank.fb, report.json
python -m pipeline.golden                     # core/trace/testdata/golden.json for the Go tests
```

| Module | Role |
|---|---|
| `suite.py` | The 36-prompt reference suite and the test-challenge generator |
| `collect.py` | `run`: collect the suite for one model through OpenRouter · `import`: file staging output into `data/records/` |
| `records.py` | The records tree `data/records/<vendor>/<label>/<route>.jsonl` and its shared row format |
| `references.py` | Load records into bank rows (validity, first valid answer per prompt, merges, completeness) |
| `parsing.py`, `features.py` | Reply → numbers → feature vectors (mirrored in `core/trace`) |
| `scoring.py` | Reference scorer, the Python twin of the Go core |
| `build.py` | Fit the bank, calibrate it, measure per-model accuracy, set the known-model thresholds |
| `family.py` | Family (vendor) classifier: logistic regression over both feature blocks |
| `export.py`, `mtfb/` | Binary bank writer (`schema/bank.fbs`; `mtfb/` is generated by flatc) |
| `golden.py` | Golden test cases the Go core must reproduce |
| `config.json` | Vendors, merge groups, route filters |

## Adding a model

1. Collect all 36 prompts: `python -m pipeline.collect run --model … --provider … --label … --out staging/x.jsonl --budget 1`.
   Run it again until the summary shows nothing left; partial models are left out of the bank.
2. `python -m pipeline.collect import staging/x.jsonl` files the answers under `data/records/<vendor>/<label>/<route>.jsonl`.
3. `python -m pipeline.build`, check `data/bank/report.json`, then `python -m pipeline.golden`.

Two versions that cannot be told apart (pooled affinity around 0.998) go into `config.json` → `merge` as one group.

## Verdict levels

`scoring.tier()` turns a result into one of: `match` (top model probability ≥ 0.80 and a normal
fit), `family` (the vendor is clear: family probability ≥ 0.80), `uncertain`, or `unknown`. A
"weak fit" means the closest model fits worse than 99% of genuine held-out answers; it turns a
would-be match into `family` (probably an unlisted version of that vendor), and only a weak fit
with no clear vendor is `unknown`. Anything but `match` asks the user to name the model. The family probability averages the family classifier with
the model probabilities summed per family.
