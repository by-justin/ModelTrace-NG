# web

The public site: static, paste-only, scoring in the browser with the TinyGo build of `core/trace`.

```bash
npm ci
npm run dev        # copies ../data/bank/bank.fb and ../core/build/trace.wasm into public/ first
npm run build      # dist/ — deploy anywhere static (GitHub Pages builds it from CI)
npm test
```

Build the WebAssembly scorer before the first run:
`cd core && tinygo build -o build/trace.wasm -target=wasm-unknown -no-debug -opt=z ./cmd/wasm`.

## Optional API

`public/config.json` holds `{"apiBase": null}`. With a URL there (for example
`{"apiBase": "https://api.example.com"}`), each analysis is also shared with the API in the
background, stamped with ALTCHA proof of work solved in web workers. Sharing can be switched off
on the result page; when it is off, when no API is configured or when anything fails, nothing is
sent and the user sees no error. The site never sends replies to the API for scoring.

A shared result (`modeltrace-submission/1`, built in `src/api/submit.ts`) contains the challenges,
replies, the verdict, an optional user identification when the verdict is not a clear match, and a
FingerprintJS browser fingerprint (long component values replaced by their SHA-256). The API adds
the IP address and request headers.

## Layout

| Path | |
|---|---|
| `src/core/scorer.ts` | Loads `trace.wasm` and `bank.fb`; `count`, `minimum`, `categorize` |
| `src/core/challenges.ts` | Test prompts (Chinese templates match `pipeline/suite.py`) |
| `src/core/fb/` | Generated by `flatc --ts -o web/src/core/fb schema/bank.fbs` |
| `src/api/` | Optional contribution: config, stamp, fingerprint |
| `src/pages/` | Test, Result, Models, How it works |
| `src/i18n.ts` | English and Chinese strings |
